# 数据、备份与诊断

默认数据根为 `~/Library/Application Support/Mox/`。App 环境变量 `MOX_DATA_ROOT` 或 CLI `--data-root` 可选择独立根；这只改变根位置，不自动搬移已有数据。正常使用无需管理员权限。

| 位置/介质 | 所有者与用途 |
| --- | --- |
| models/artifacts、models/staging | Mox 托管的不可变模型及暂存文件 |
| runtime | 服务独占的 SwiftData 配置、安装、下载索引 |
| conversations | GUI 对话组件独占的会话、消息和生成尝试 |
| run | 实例锁/发现；包含管理凭据，不应上传 |
| macOS Keychain | 来源/镜像凭据和独立公开 API key |
| UserDefaults / Unified Logging | 原生界面偏好 / 脱敏系统日志 |

引用导入不复制模型，不取得原目录删除所有权。管理动作经服务与 Core 准入；不要直接编辑 manifest、SQLite 或 SwiftData 文件。未知旧开发期数据根须先识别格式并保存完整备份；不为未发布旧实现保留兼容入口，也不自动丢弃不识别的数据。

## 备份与恢复

先停止拥有该数据根的服务，退出使用该对话库的 App，再完整复制数据根（包括数据库的伴随文件）；不要运行中只复制一个 sqlite 文件。Keychain 凭据不随这个目录副本迁移；更换机器应通过系统 Keychain/迁移助理或重新设置凭据。

目前没有通用“备份/迁移/恢复”CLI。保留副本，在独立根上确认可打开后再进行人工恢复；不得以恢复为由覆盖唯一副本。不要把自己的模型、会话、数据库或凭据放进 Git。本次仓库整理没有访问或修改默认用户根。

服务启动恢复会检查受管文件，补安装索引与下载任务。缺失/损坏项保留记录和诊断，不阻断健康模型；不能加载未校验的托管产物。对话重开将未完成尝试标 interrupted，不自动重发生成。打开 store 失败必须显示错误，不能假装空库；保存失败留内存文本供显式重试。

## 诊断与报告

App 服务控件可显式导出脱敏诊断，包含版本/配置、运行状态、安全阶段/错误码与 request/operation/instance 标识。服务诊断不可取得会明确标记，并保留可取得的本机诊断。下载页可查看任务 ID 与错误；参数保存失败保留编辑草稿。

默认不记录 prompt、回复正文、工具输入/结果、密钥、完整文件路径或含凭据 URL。Unified Logging 使用 subsystem `dev.mox`；导出前仍应检查是否含私人信息，尤其不要上传 run/discovery、Keychain 内容或完整数据库。构建/测试失败日志位于对应 `.build` 目录，问题模板要求提供版本和最小复现而非私有数据。

基础排查：确认同一根只运行一个所有者、CLI/App 指纹一致、Keychain 允许访问、模型必要资产齐全。报告不可恢复错误时保留原数据和隔离复现；不要删除数据目录来“修复”。安全问题按 [SECURITY](../SECURITY.md) 提交。
