# 0.1 原型至公开发布计划

状态：执行基线；2026-09-06。用户已确认分里程碑实施，具体出口见各阶段规格。用户本轮明确：0.1 仅自己进行原型与功能验证；Codex 不作为目标，Pi 后置，签名公证与 Homebrew 延至公开发布阶段。流程遵循 [CONTRIBUTING](../CONTRIBUTING.md)。

## 发布定义

0.1 是本机文本与工具调用的功能原型：本地构建的 App 选择来源与模型、下载并聊天；开启标准 API，用真实 HTTP/SDK 测试程序验证。无需接入指定 agent，也不要求公开分发。不是全部远期功能完成。多模态确定后续实现，Pi 可选集成、复杂 batching、自定义 kernel、分布式不在 0.1。

App 不依赖用户安装 brew/Python/Node；仅 Apple Silicon，最低 macOS 15 为待实际验证的支持下限。不可因开发机较新未经说明提高下限。SwiftData、官方 MLX、原生 GUI 与已定进程所有权不重选。

## 全局契约索引

唯一技术规格为 [TECHNICAL-DESIGN](architecture/TECHNICAL-DESIGN.md)：模块 §2；实例/鉴权/所有权 §3；来源身份 §4；安装原子性 §5；预算/lease/cancel-and-wait §6；有序消息、终态及参数 §7；协议 §8；存储 §9；GUI/发布/诊断 §10。阶段规格细化实现范围，不能静默改变这些不变量。

G0–G7 是验收维度而非额外串行预研：M1 覆盖 G3 与 CLI Metal 资源；M2 覆盖 G1/G2/G5 及 App 资源；M3 覆盖 G4 及管理存储/GUI；M4 完成 G6 和本机全链路回归；P1 完成 G7 公开分发。已完成 Xcode/SwiftData 验证无需每会话重跑。

## 首版必须具备的工程质量

关键状态和异常有稳定错误码；请求/实例关联诊断且默认不含输入、输出和凭据；下载、日志、流式缓冲有界；真实取消和内存回收；明确区分服务健康与模型可用。自动测试覆盖业务规则及失败竞态，真机验证不能被 mock 替代。没有任意覆盖率数字目标，关键要求必须逐条有证据。

记录可复现性能基线（冷加载、TTFT、生成、内存、取消）；初始数值是测量结果，不许编造硬件通用承诺。不以“不追求性能”省略资源正确性。

## 后续决定及处理时间

0.1 当前无阻塞性的用户范围问题。M1 按详细规格实施，M2–M4 在进入阶段时定稿技术细节。

- P1 前再确定是否公开发布、签名 Team/bundle ID、发布仓库和 Homebrew tap；缺账号不阻塞原型。
- macOS 15 下限、测试模型与依赖组合由工程验证，发现实际冲突再讨论。
- Pi 后置，不要求 Codex/Responses。标准 OpenAI/Anthropic API 仍需真实请求和工具往返验收，不要求商业 agent 客户端。
- Apple container 仅作为未来 Pi/工具执行隔离候选，未选定依赖；不改变 MLX 在 macOS 宿主运行的架构。

本计划不授权购买账号或外部发布。公开发布另设 P1，原型完成不得表述为公开发行完成。
