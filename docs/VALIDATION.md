# 验证范围与限制

Mox 0.1.1 是源码原型。自动测试、独立代码复核和用户体验验收是不同环节，不能相互替代。可复跑命令、环境准备和测试隔离要求见 [开发与测试](DEVELOPMENT.md)。具体提交的自动检查结果见 [GitHub Actions](https://github.com/Neofly1992/mox/actions)。

## 已覆盖的验证层

- 规则与集成：Core 业务规则、SwiftData 持久化、下载恢复、HTTP 协议与连接生命周期、并发取消、参数继承及迟到预览结果隔离。
- 本地 Apple Silicon 端到端：真实 MLX 生成、取消与重试、官方 OpenAI/Anthropic SDK、CLI、服务重启及打包产物检查。
- 原生 GUI 自动化：模型与会话操作、参数来源、恢复默认和生成交互。自动化不代表用户已经完成体验验收。
- 来源：公开 Hugging Face / ModelScope 的真实请求另设联网测试；普通规则测试会跳过这些用例。

这些是项目已有验证覆盖，不表示每次提交都重跑全部矩阵。变更的实际命令、被测提交及未运行项目应记录在 PR 或交付说明中；原始日志与内部交接记录不随源码分发。

## 尚未确认的范围

- macOS 15 真机兼容性；部署目标不等于已验证的运行环境。
- 私有来源、私有镜像及其真实凭据组合。
- 全部模型、硬件、上下文长度组合与超大模型库的实际性能。
- 完整人工体验验收及签名、公证、独立安装包分发。

本地只读模型引用使用文件元数据检查，不能发现刻意保持大小和修改时间不变的内容替换；托管下载模型的完整性流程见 [架构](ARCHITECTURE.md)。安全边界见 [SECURITY](../SECURITY.md)。

## CI 与发布的关系

普通 CI 检查仓库一致性和规则/集成测试，不持有发布权限。独立二进制工作流实际检查 Xcode/Swift/Metal 并构建完整 App、生成 ZIP/SHA-256，检查解压后版本、ARM64、资源、worker 身份和 ad hoc 签名；不执行真实 MLX、GUI 或来源联网验收。发布安全回归使用 GitHub API 替身，覆盖中断续传、starter 空附件冲突及重建后的恢复，不代表真实 Draft 已上传。上传任务的短期 GITHUB_TOKEN 权限和 environment 保护仍需真实发布流程验证。

手动标签工作流只上传 Draft 的 ad hoc 未公证实验包，不自动公开；正式 Developer ID 签名、公证及 Gatekeeper 安装验收未完成。远端构建结果以具体 Actions 运行和 commit 为准，定义工作流本身不是成功证据。最终真实 MLX 与 GUI 验收必须使用从 Release 下载的同一附件，记录 SHA-256；开发分支 artifact 或本地构建的结果不能替代。操作见 [发布说明](RELEASE.md)。

## 诊断与安全预算的验证边界

doctor 和资源准入的规则测试使用可注入检查/压力信号；它们验证响应与生命周期，不证明 macOS 实际压力事件总能提前于 OOM，也不校准所有架构的实际峰值。真实路径入口另见 DEVELOPMENT，必须记录本轮执行结果。资源评估采用稠密模型保守包络，缺配置/未知架构不推荐；CLI/GUI 预览不是运行授权。MLX active/cache/peak 为分配器观测，不能冒充系统余量或单请求实际占用。

目前没有用真实系统严重内存压力测试保护，也不要求通过耗尽整机内存来验证。macOS 15 真机、所有模型/量化/config 组合、私有镜像/真实凭据和人工体验验收继续属于未确认范围。注入信号、替身通过和真实 MLX/HTTP/GUI 的结果须分别报告。

异常文件验证覆盖命名管道、目录和设备类型拒绝，以及资源预览后的服务可用性与退出。分块取消和非阻塞打开不保证能中断任意文件系统内核阻塞；不得把检查期限描述为所有存储故障下的硬实时保证。只读断言使用结构化状态及持久化写入计数，JSON 对象编码字节顺序不作为状态等价依据。
