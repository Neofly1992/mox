## 设计与失败路径结论

- 公共 listener 默认关闭，独立持久 key 留在 Keychain；管理 token 仅私有 listener 可用。API 只接受已安装模型 alias/ID，不允许公共请求指定任意路径。App、CLI 和 HTTP 复用 `InferenceService`/`RuntimeCoordinator` 的准入、取消与 lease。
- MLX 对 Qwen3 使用官方聊天模板 `enable_thinking=false`，让 `<think>` 内容不作为正文输出；工具 JSON 由官方 parser 完整识别后才形成领域事件，wire 再分片。锁定版 parser 的 chunk 标签扫描限制通过标量输入适配，未实现第二套模型格式解析器。
- 不支持的 Responses API、工具强制选择、媒体、浏览器 Origin 等均明确拒绝。错误状态和事件见 M4 规格；HTTP 错误正文不含 key、请求正文或本地模型路径。公共请求不保存到 App 会话。
- 真实私有自定义镜像需要用户可访问的地址与凭据，macOS 15 需要对应设备；两项标 **BLOCKED（外部资源）**，不声称已验证。M2/M3 的用户体验验收仍待原报告流程，不因本报告更新而改变结论。

## 用户人工验收

1. 打开 [Release App](../../.build/m4/Release/Mox.app)，在“模型”获取 `mlx-community/Qwen3-0.6B-4bit`，查看详情并在“测试”发一条消息；确认下载、错误提示与聊天体验。
2. 开始较长回复后点停止，再生成；退出并重开，确认模型与测试会话可见且中断不会伪装成成功。
3. 在“本机 API”开启服务，检查地址、两协议连接示例与密钥显示/复制是否清楚易用。两 SDK 的协议和工具往返已自动验证，无需用户重复运行测试脚本。
4. 重置 key、关闭并重新开启 API，评估状态与诊断文案。旧 key 拒绝、关闭后连接失败和恢复均已自动验证，无需用户执行协议测试。
