# 模型工作台：信息架构与用户动线提案

状态：**用户已确认交互方向并授权 M2 实现**。2026-09-14。产品定位以模型的获取、管理、运行为中心；对话是模型测试环境。本文是交互设计提案，不是已实现能力或 M3 可执行规格。

## 推荐结构

应用一级导航为「模型」「下载任务」「测试」「API 服务」，底部持续显示服务连接入口，设置使用原生设置窗口。默认进入模型页。模型页内「本地 / 获取模型」是同一对象范围的切换；模型详情在同一内容区钻取，返回保留原列表位置和筛选。不常驻额外详情栏，不叠加一排无关功能标签。

下载任务为跨页面、跨会话的长期任务，独立集中处理。模型页显示关联任务的简短摘要和定位入口，不再复制一套暂停/恢复业务。测试保留独立入口，也可由模型详情带入选择；测试记录属于测试区域，不占应用主侧栏。

## 主要用户动线

1. 首次使用：模型空状态 → 选择本地目录，或获取模型 → 选择来源、版本和量化 → 下载任务 → 校验及安装 → 查看模型 / 测试。完成后提供动作，不强制跳转打断其他工作。
2. 日常管理：本地模型列表 → 详情 → 看文件与运行状态 → 加载/卸载、管理默认设置、删除或进入测试。未加载也能点测试，按既有契约自动加载。
3. 验证模型：详情 → 测试（已带入模型）→ 调整本次参数 → 发送、停止、重试 → 看结果与记录 → 返回模型。临时测试参数不自动覆盖模型默认值；需要显式保存为默认。
4. 处理下载：任意页面看到任务数量或关联摘要 → 定位下载任务 → 暂停、继续、处理错误或移除。导航和关闭窗口不取消任务；退出仍遵循真实服务所有权及活跃任务确认契约。
5. 外部使用：模型管理完成 → API 服务页选择允许调用模型、协议及固定版本并取得调用信息（M4）→ 外部客户端调用。内置对话不是必经步骤。

## 四类状态各有归属

| 状态 | 展示位置 | 规则 |
| --- | --- | --- |
| 文件可用性 | 本地列表与模型详情 | 已安装、本地引用、路径失效；仅下载字节完成不能标成可用。引用移除不删除外部文件。 |
| 获取任务 | 任务中心；模型页关联摘要 | 获取文件信息、排队、下载、暂停、校验、安装、完成、可恢复失败、取消。已安装旧版本与新版本获取任务可以并存。 |
| 运行状态 | 模型行与模型详情；测试上下文 | 未加载、加载中、已加载、使用中、卸载中、失败；不与文件状态合并成单个含糊标签。不虚构 GPU 加载百分比。 |
| 服务连接 | 全局底部入口；异常在当前内容区提示 | 正常时低干扰，异常时保留历史数据并标最后已知/待确认，限制需要服务的操作；断连不等同于任务失败。 |

总大小已知时显示字节、百分比、测得速度与可信剩余时间；未知时显示已下载字节和当前阶段，不伪造百分比/剩余时间。校验和原子安装使用阶段提示，不能用“100%”表示全过程已完成。服务重连后先核对快照，再恢复操作。

暂停保留任务与已下载文件。不再提供“取消后可继续”的重复状态；「取消下载并清理…」明确丢弃该任务未完成的文件，保留已安装版本，操作前说明清理范围。网络中断、磁盘不足、鉴权失败及校验失败各自给出原因和对应恢复动作；不得把所有问题变成一个“重试”按钮。校验失败的重下范围、安装临界段的取消边界由 M3 规格确定。

更新下载不改变正在使用的旧快照；新版本校验安装成功后才切换可用引用。模型正在使用时的卸载/删除必须说明占用及可执行动作，不通过强制结束其他客户端任务来完成。

## 版本、更新与自定义来源

模型列表以名称、量化和可用状态为主；来源、跟踪分支/tag与精确安装revision可在详情查看；本地引用未登记来源时明确未知，不反推仓库。模型详情提供检查更新、查看差异、下载新版本和显式切换。更新安装成功前旧快照继续可用；切换当前模型不自动更改API固定版本，也不更改在途请求。固定commit不能被当成移动tag自动更新；不同仓库/模型代际不是普通版本更新。

来源管理提供显示名称、provider协议、origin、可选镜像和凭据引用。HF/ModelScope及同协议自定义实例在范围内；镜像不改变来源身份，OCI和任意网站不是自动支持。来源的选择与连接设置共用权威配置，凭据正式实现使用Keychain。

## 测试与能力驱动的参数

测试内部划分对话测试、Agent测试（后续）。对话可保留多份多轮记录，默认仅一份活动生成；记录位于测试内部，包含模型精确版本、实际参数、输出、终态和性能。新测试不覆盖旧记录。测试区使用可收起的会话列表，包含名称、模型、时间和状态。每份会话保留多轮；重试最后一轮新增回答尝试，旧结果可前后浏览，继续提问使用最新尝试作为上下文。浏览旧结果不改变后续上下文。

停止先进入“正在停止”，服务确认后才显示“已停止”；失联标“结果待确认”，重连核对后再允许新请求，不推断资源已释放。生成失败保留内容并提供重试。保存状态独立显示：未保存时保留窗口内数据并提供重试保存，不把它描述为生成失败。原型用情景按钮模拟这些分支，不代表真实持久化或服务测试。Agent记录另外保存工具过程、运行结果和文件改动；环境清理不删除记录。

参数默认折叠并使用模型默认设置。展开显示支持项、实际默认值和来源，支持恢复默认；本次覆盖与模型默认设置分别保存。上下文预算与输出上限分开，不允许超出模型/后端/资源的有效边界。思考开关、思考预算不是同一能力，未知能力不提供假控件。能力描述由模型配置、模板、固定后端及真实验证共同决定；GUI/CLI/API共享服务端校验，不能只凭名称或模型卡生成可用承诺。

Agent测试展示一次性项目副本、工具许可、网络和凭据边界，以及停止/清理入口。隔离技术与Pi集成留到后续阶段核验；独立工作目录不等于沙箱。原型仅模拟执行，不启动真实环境。

## API 服务

独立页面管理服务开关、本机endpoint、公开协议、访问凭据与允许调用的模型清单。每个模型配置对外名称、允许协议及固定安装版本；名称唯一。未允许的模型必须由服务拒绝调用，不能只隐藏列表。允许调用与已加载分开：请求到来可自动加载，不为每个模型另启服务。

公开推理凭据与管理凭据隔离，默认仅loopback。模型当前版本切换后，固定版本的API名称仍指向旧快照，用户可显式重新配置。模型详情直接区分新测试版本和 API 使用版本；客户端连接信息从具体已允许模型进入，按其协议、别名和固定版本展示可选中复制的请求示例及占位key；OpenClaw/OpenCode实际兼容性须在M4核验，不凭“兼容OpenAI”概括保证。

## 分阶段落点

M2 若确认调整：确立模型为默认入口、独立测试区域、全局服务状态及可返回的模型详情。内容来自当前本地目录与已有聊天中的最近使用路径，标为「最近使用的本地目录」，不声称是完整安装清单。不为临时界面新建第二套模型数据库；选择路径仍经真实 Core 校验，历史路径不代表仍有效。只提供本阶段已有能力，不显示不可用的下载/删除按钮。

M3：在相同导航结构填入服务权威的模型目录、获取子页和下载任务中心；增加安装、管理和恢复行为。模型页的数据来源通过清晰边界从本地路径上下文转向安装快照，测试接收明确模型引用及冻结参数，不依赖列表行或某个详情视图。任务状态与模型状态分别建模，在 UI 层组合展示，不把下载状态塞入会话对象。

M4加入API服务管理和经验证的协议；完整设计中的Agent页属于后续阶段。原型可切换M2/M3/M4/完整设计，不把后续页面作为当前App已实现能力。

本阶段预留的是页面职责、导航上下文、状态归属及模块依赖；不预建空服务、下载协议、通用插件框架或假按钮。M3 的持久化、来源与状态机必须按实际接口细化和验证，不能把视觉原型当成实现规格。

## 设计审阅

可交互稿演示：模型 → 详情 → 测试，获取 → 下载 → 暂停/继续/取消并清理 → 校验安装 → 模型；支持 M2/M3/M4/完整设计、首次使用与下载异常状态预览；可编辑模拟API配置、自定义来源和参数，演示更新安装后切换版本及Agent执行/清理。所有模型大小、速度及进度均为示例，不连接真实服务，不修改本地模型。

推荐采用稳定侧栏 + 局部范围切换 + 内容区详情。常驻三栏会挤压模型信息及测试空间；把全部功能平铺成顶部标签会混淆全局模块与模型上下文，因此不作为首选。

独立设计审查基于源码与提案认可信息架构，不包含视觉验收。交互稿补齐会话列表、多轮重试和停止/失联/未保存情景；API、版本和 Agent 仍属后续设计。

已确认整体层级、管理到测试的动线及下载任务组织方式。M2 落点见里程碑规格，实际实现与自测证据见 M2 交付报告；自动测试不代表用户已验收界面，后续能力仍按各阶段细化。
