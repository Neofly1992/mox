# M1：可靠运行本地文本模型

状态：待人工验收。实现者自测完成，2026-09-07；[验收报告](../acceptance/M1.md)。独立审查未进行，尚无人工验收结论。

## 用户审阅概要

交付最小 CLI：选择已有的受支持 MLX 文本模型，输入问题，逐步看到回复，可停止并继续提问。错误可理解，退出释放资源。无下载、GUI、HTTP、持久模型目录、工具执行、多模态或性能引擎。工具与媒体输入在本阶段明确拒绝，不静默当文本处理；0.1 的工具支持仍由 M4 交付。

入口：当前新骨架、完整 Xcode 已具备；真实模型由实施者检查可用目录，记录来源/变体/revision（未知明确说明）。不要求用户反复安装工具链。没有测试模型可继续规则测试，但不能提交为待验收。

## 命令与用户行为

`mox chat --model-path PATH [--prompt TEXT] [--max-tokens N] [--temperature T] [--top-p P]`。

有 --prompt 为一次性请求；省略则交互会话，多轮保留本进程上下文。stdin 非终端且无 --prompt 时返回参数错误，避免挂起 CI。模型从指定目录只读加载，不访问网络、不修改权重/配置，不把路径当远端 ID。支持带空格和 Unicode 的路径。

交互中 Ctrl-C 停止当前工作并回到输入；空闲 Ctrl-C 或 EOF 退出；SIGTERM 协调退出。一次性 Ctrl-C 取消并退出 130，SIGTERM 143；正常 0，参数错误 2，加载/运行/资源错误 1。stdout 只输出回复文本，提示、阶段和诊断到 stderr。此阶段不承诺 JSON CLI；机器事件由 Core 测试验证。

## 可验证要求

| 编号 | 行为与错误契约 |
| --- | --- |
| M1-R01 | 缺目录、缺必要资产、不支持模型、非法参数在可判定的最早阶段失败；不自动下载/转换，不泄露完整 prompt |
| M1-R02 | 规范化本地引用，检查配置/权重/index/tokenizer 必需资产，调用官方 factory/processor；加载失败回滚，可在同进程重试。外部目录推理期间不得改写，不承诺阻止其他进程修改 |
| M1-R03 | 生成请求使用有序消息内容块；采样参数仅解析一次。max tokens 默认 2048、上限 8192并受上下文/预算限制；非正整数、非有限数及不支持参数拒绝。temperature 范围 0–2，top-p 范围 (0,1]；temperature=0 使用上游贪心语义 |
| M1-R04 | 事件含 request ID、单调序号和真实内容增量；单一终态 finished(stop/length/cancelled) 或 failed。可用 usage 从上游取得，未知不填虚假 0；不按字符估算 token |
| M1-R05 | cancel 幂等，waitUntilStopped 等实际 backend/GPU 结束；释放 lease 仅一次。取消后正常再次生成；取消/自然完成竞态仅一个终态，终态后不发增量 |
| M1-R06 | Coordinator 是唯一资源权威，共享同一模型加载；单 GPU 工作调度显式实现，等待者取消不破坏其他等待者。队列容量8、等待60秒为初始可配置内部策略；满/超时报明确错误 |
| M1-R07 | 先 reservation 再 await，失败回滚；使用中不能卸载，正常退出取消并等待再卸载。保守预算区分 weights/KV/峰值，未知不得假定固定4GB；无法安全容纳拒绝，记录估算依据 |
| M1-R08 | 输出链路有界；慢消费者超限取消并失败，不能丢 chunk 后成功。检查上游内部缓冲；外层 bounded stream 不能作为上游已受控的证明 |
| M1-R09 | 交互多轮只把成功完成的问答加入后续上下文；取消/失败的部分回复可显示但不加入下一轮。上下文超限明确报错，不静默截断。保留 session 与 generation 的区别 |
| M1-R10 | 日志包含 request/model operation 标识、load/prefill/decode/cancel 阶段与耗时，默认不含 prompt/回复/密钥；CLI stderr 无管道死锁。构建产物在源码目录之外也可找到 Metal 资源 |

M1 实施的资源安全边界：tokenizer 处理后的输入最多 8192 tokens，原始文本最多 1 MiB；输入加输出上限须满足模型 context。当前支持具有已实现 dense-attention 预算估算的配置，未知架构拒绝。具体依赖、架构列表、预算依据与有界回调选择见技术设计 §13。

参数范围是本阶段产品约束，不宣称所有模型原生相同。stop sequence、tool choice 的完整 wire 语义由 M4 细化；本阶段内部不支持的字段应明确失败。

## 模块契约与实施边界

Domain：Sendable 值类型、错误与事件；Core：解析后的请求、RuntimeCoordinator、backend 端口与句柄；MLX adapter：官方加载/生成、GPU 等待、统计；CLI：ArgumentParser 与 IO/信号；具体命名自行确定，不暴露 SwiftData/MLX 类型给 Domain。

Generation handle 必须有事件消费、cancel、waitUntilStopped。定义唯一任务所有者，不返回无终态字符串流。Core 可接受可控测试 backend 做资源/竞态验证，不能增加只为测试的生产捷径。

M1 CLI 可直接组装 Core，M2 将普通 chat 接到服务 client，并把组装放在 serve；不得形成第二套推理用例。不为尚未需要的数据库、HTTP、GUI 建空模块。依赖使用核验过的稳定版并锁定；官方 API 不符合预期时报告证据，不能悄悄手写推理引擎。

## 人工验收（报告中填入实际产物与模型路径）

1. 一次性中文问答，流式可见且正常退出。
2. 交互连续两轮，第二轮能使用第一轮上下文。
3. 长回复时 Ctrl-C，停止后仍可继续一轮，最终退出无遗留进程。
4. 不存在目录与非法参数，错误清晰且无下载/文件改写。
5. 在工程目录之外启动交付产物，结果正常；按报告获取脱敏诊断。

这些是行为判断，不要求自由生成回复逐字一致。无必须由用户选择的 M1 产品未决项；具体模型选择与资源问题由实施者调查后记录。
