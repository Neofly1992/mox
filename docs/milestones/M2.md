状态：规格概要；进入本阶段前细化为可实施规格。尚未实现或验收。

## 入口

M1 已验收；生成/错误/取消契约有证据。进入编码前定稿私有 API DTO、事件帧、身份发现、App 打包和聊天 schema。

## 范围与要求

| 编号 | 必须交付的行为 | AI 验证方式 |
| --- | --- | --- |
| M2-R01 | App、前台 serve 和外部托管共用实例；锁竞争唯一 owner，身份不符/端口冲突明确失败；GUI 不终止外部服务。 | 真实进程竞争、伪健康端口、迟到 ready、父进程消失和正常退出。 |
| M2-R02 | CLI chat 和 GUI 走同一 Client/服务；移除 M1 CLI 的直接推理组装，serve 作为 composition root；无每轮 subprocess。 | 两种 client 真实流式/取消；断连取消生成；body 在聚合前限额，慢读/超限不泄漏。 |
| M2-R03 | GUI 原生文件选择本地模型、基础 Markdown 对话、停止、重试；服务状态与模型状态分别显示，长文本不阻塞交互。 | XCUITest 首次启动、本地聊天/停止/重试；长输出与滚动、过期事件隔离。 |
| M2-R04 | App 唯一拥有 ConversationStore；明确保存终态和 checkpoint；重启恢复部分回复为 interrupted，不自动重放生成。 | 真实 SwiftData 重开、写失败、异常中止；失败不清空库。 |
| M2-R05 | 诊断按实例/请求关联，有界且脱敏；App 内置同版本 worker/Metal 资源，无开发目录或 PATH 依赖。 | 源码目录外 App 启动，日志字节上限与管道排空；无需 brew/Python。 |

## 非目标

不含下载、公有推理 API、正式签名分发。GUI 基础能力必须真实可用，不能先留所有按钮占位。

## 出口

所有必需要求有通过证据，按 CONTRIBUTING 创建 `docs/acceptance/M2.md`，附精确版本/命令/产物、限制和人工步骤。未测必需项不得标待验收。用户明确验收后才标已验收。

## 人工验收场景

1. 打开 App，选择本地模型并聊天。
2. 停止长回复并重试，界面可操作。
3. 退出/重启后查看历史；关闭窗口不退出服务。
4. 连接前台已有服务，退出 App 后服务继续运行。
5. 模拟服务异常，看到可定位的错误和诊断。
