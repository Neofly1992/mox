## 目标与范围（供用户审阅）

打开独立 Mox.app，默认进入模型工作台；选择本地模型目录，在详情中点击“测试此模型”即可进入对话测试，不用先启动终端服务。已有同版本服务时连接它；服务来源可见。消息逐步出现，加载或生成期间可以停止，等待真实停止后继续；失败和部分回复保留。关闭窗口继续运行，退出应用会保存聊天并协调关闭自己启动的服务，外部服务继续运行。重开能看到历史与中断标记，不自动重发消息。

## 1. 实际 M1 接口与必要扩展

Core 仍为唯一运行权威：`RuntimeCoordinator.generate(model:request:) -> GenerationHandle`、`snapshot()`、`unload`、`shutdown()`；Server 不自建 GPU 门闩、预算或模型缓存。`GenerationHandle` 单消费者，`cancel()` 幂等，`waitUntilStopped()` 等待 backend 与 lease 释放。非终态队列 128 帧/256 KiB，加一个保留终态槽；不能在 Server 或 Client 另接无界 AsyncStream 抵消它。

现有 Domain `GenerationRequest` 含 UUID、消息内容块与 Sampling；保持 1 MiB 文本、8192 输入 token、maxTokens 1…8192、temperature 0…2、topP (0,1] 及模型上下文校验，不在 HTTP 重写另一套采样业务规则。wire DTO 单独 Codable 映射，再调用现有验证构造器；拒绝未知字段、未知块与非文本语义。用户模型选择经 Core 的 `LocalModel` 校验，客户端不声明模型有效。

现有事件序号从 0 开始：`phase(accepted/queued/loading/prefill/decode)`、`contentDelta`、`usage`、`finished(stop/length/cancelled)` 或 `failed`。loading 当前涵盖 tokenizer 与 warmup；prefill 包括 prepare 到首个 token，GUI 不虚构细分进度或百分比。`RuntimeSnapshot` 目前仅计数，M2 在 Core 增加每模型只读状态和活跃请求快照，由同一资源状态派生；不让 Server 根据曾出现 loading 推断 ready。

加载使用共享 detached task，单请求取消不会取消其他等待者的加载；可能等待加载/warmup 完成后才停止，驻留模型可保留。同步 MLX prefill 在官方回调前无法保证瞬时取消。终态不能早于实际回收请求 lease；正常取消不要求卸载空闲模型，服务 shutdown 才要求驻留、预留、lease 全部归零。

`ChatSession` 当前仅将 stop/length 成功轮次加入上下文。GUI 延续该规则；增加共享的纯上下文选择规则供 CLI 与持久历史使用，UI 不复制规则。CLI 不再直接组装 MLX；唯一运行组合入口为 `serve`，CLI 会话复用一个服务连接，不逐轮创建进程。

## 2. 模块与服务所有权（M2-R01）

- Domain：值类型、错误及共享上下文规则；Core：校验与 runtime；MLX：官方适配。
- Server → Core：Hummingbird 私有 HTTP；Client → Domain：URLSession、wire 验证与流处理；协议 DTO 放轻量共享 target，禁止 Client 为 DTO 引入 Server/MLX。
- Bootstrap → Domain：canonical root、flock、discovery、Process 和父子管道。`serve` 注入 Core/MLX/Server，App 注入 Client/Bootstrap/ConversationStore，App 主进程不加载 MLX。
- Persistence：独立 SwiftData ConversationStore，唯一逻辑写入者是 App；服务不写聊天正文。多窗口共用一个 store actor；同 root 第二个 App 只激活已有 App，不能打开第二写入者。CLI 不访问该库。

canonical data root 默认 `~/Library/Application Support/Mox`，测试传独立临时 root；解析符号链接，创建后再取规范路径。run 0700，文件归属当前 UID、discovery 0600；拒绝不安全权限/符号链接，不读取任意外部凭据。flock FD 全程持有且 close-on-exec，不 unlink 锁文件导致不同 inode 双 owner。

拿锁 → 初始化与恢复 → bind `127.0.0.1:0` → 原子发布 discovery；任何失败按逆序回收。discovery 包含 schema=1、instanceID、PID、UID、rootIdentity、buildID、protocolVersion=1、ownership、privateEndpoint、随机至少256-bit token。PID 仅诊断，绝不凭 PID 杀进程。buildID由生产Swift源码、依赖锁与构建脚本的确定性SHA256生成，App和worker共用。身份握手严格匹配 buildID/protocol/root/instance/owner，端口能连或 HTTP 200 不足以证明有效。

`foreground`/`externallyManaged`/`appOwned` 复用同一 serve；显式 serve 竞争失败非零，不偷偷连接后假装启动成功。App 启动竞争失败者只连接已验证胜者。外部实例版本不符显示升级/重新连接提示，不启动第二实例、不自动停止它。陈旧 discovery 仅在获得 root 锁后替换。

App 自启 worker 使用 bundle-relative 路径，持有 Process handle 与专用继承管道；凭据/控制能力不走 argv。父管道 EOF 触发 worker drain；控制 FD 不传给其他进程。只有确实启动并持有该 worker 的 App 有关闭权；连接已有 appOwned 实例也不等于自己拥有。ready 等待上限15秒，超时仅清理己方子进程，迟到 ready 不改变新连接 epoch。外部服务故障不得被自动接管。

## 3. 私有通信协议（M2-R02）

UTF-8 JSON，camelCase 字段；所有路径前缀 `/mox/v1`，无公有路由。每次请求 bearer token；拒绝 Origin、重定向和非指定 loopback origin，URLSession ephemeral，无代理、无缓存/credential persistence。token 不出现在 URL、错误或诊断中。服务响应携带 instanceID，client 绑定当前 epoch。

| 端点 | 请求 | 响应与语义 |
| --- | --- | --- |
| GET `/identity` | 认证 header | JSON identity：上述身份字段但无 token；buildID 精确匹配。 |
| GET `/state` | 无 body | instanceID、revision、serviceState(running/draining)、libraryRecovery{phase,inspected,errorCode}、ownership、runtime 计数、models[{modelID,state,verifiedProfile}]、requests[{requestID,modelID,phase,stopping}]；不含正文/完整路径。 |
| POST `/generations` | `{requestID,model:{kind:"localDirectory",path},messages:[{role,content:[{type:"text",text}]}],sampling:{maxTokens,temperature,topP}}` | 预验证后 `200 text/event-stream`；认证/JSON/模型预检失败用 JSON error；成功建立流后错误只以 terminal 帧返回。 |
| POST `/generations/{UUID}/cancel` | 空 body | 活跃请求设置取消，202 `{requestID,state:"stopping"}`；保留终态记录时200 `{state:"stopped",terminal}`；未知404。202不是已停止；流/状态用于等待。 |
| GET `/generations/{UUID}` | 无 body | 活跃阶段或终态、lastSequence；无正文，无 replay。未知404。 |

除生成POST外端点要求空body，带正文/Transfer-Encoding的请求立即400并关闭连接，避免未消费body被无界排空。关闭己方 worker 走专用父子控制管道，不提供任何 bearer 即可停服务的通用 shutdown API。SIGINT/SIGTERM 用同一 drain 路径。GET identity/state 是只读状态；模型文件路径仅用于已鉴权生成请求，按引用语义处理，不建立安装库。

错误 envelope `{instanceID,requestID?,error:{code,message}}`，稳定安全文案；transport 错误在 Client 中为 authenticationFailed / incompatibleService / connectionLost / protocolViolation。Domain 错误映射：invalidParameters/unsupportedInput/contextLimit 400，invalidModel 400，busy/重复ID 409，bodyTooLarge 413，queueFull/queueTimeout 429，resourceLimit/shuttingDown 503，loadFailed/generationFailed 500；未知请求404、认证401、Origin403。客户端显示关联ID而非底层 error.description。

请求 body 聚合前累计限制 16 MiB，包括 chunked；文本内容另按 Domain 的1 MiB限制。超限立即413并结束消费，无界 drain 不可接受。请求提交注册在验证后、运行前原子化；同实例 requestID 不复用。单个实例累计最多100,000个ID，达到容量拒绝新请求并要求空闲重启，不静默淘汰防重记录；终态详情仅保留最近256项/5分钟，超期查询404不代表成功。提交结果不明不自动重试 POST。

SSE 每帧 `event: generation`、`id: <sequence>`、`data: <JSON>` 和空行。JSON `{instanceID,requestID,sequence,type,...}`；type分别为 phase(phase)、contentDelta(text)、usage(usage:{promptTokens,outputTokens,prefillSeconds,decodeSeconds,peakMemoryBytes?})、finished(reason)、failed(error)。ID/序号必须匹配，严格递增、无间隙、一个终态且在尾部；不使用额外 `[DONE]`。未知 type/终态后内容/非法UTF-8 为协议错误，取消请求。EOF 无终态为 connectionLost，部分文本保留；usage缺失是未知，不伪造0。

Server 一个 task 消费 handle，每次写 await；写期限5秒，断连/超时 cancel并wait，finally注销，shutdown等待所有task。心跳注释每5秒，client 15秒无字节则判连接失联；心跳不产生业务sequence。单帧上限1 MiB，Client在按行聚合前按字节限额，不直接使用无界 lines 缓存；UI通道128事件/256 KiB并保留终态，输出总量上限16 MiB，超限明确失败/取消，不能丢内容后成功。

## 4. 重连、取消和退出（M2-R03）

服务连接 `disconnected → discovering → starting/connecting → running → reconnecting/unavailable`，与模型 `unloaded/loading/ready` 分开。模型错误属于请求，健康无模型服务依然 running。身份已核验的HTTP错误响应表示本次提交被拒绝，保存failed和原始错误，不按失联处理，也不对被拒绝的提交发送取消（重复ID可能指向另一个已接受请求）。snapshot 不含历史文本；读取state时 revision来自同一实例，旧epoch的帧/snapshot/ready均忽略。

失联立即保存 attempt interrupted(connectionLost)，不自动重发、补全或续接旧流。后台只重试发现/握手（0.5/1/2/4/8秒，上限15秒）；成功后先取snapshot，再允许显式新请求；原请求还活跃则请求取消并等待，不把重连当结束。实例变化时展示新来源；找不到服务显示“重新连接”按钮，用户显式重连才可在无owner时自启。请求不存在/详情过期仍保持interrupted，不猜成功。

停止意图从本地pending保存阶段起生效；远程请求尚未提交时停止会保存cancelled终态且不提交HTTP。停止立即进入stopping，禁止该聊天再次发送/重试；继续显示既有内容，接受合法在途帧但不撤销stopping。cancel响应丢失可幂等重试取消，不重试生成。终态后才开放输入；连接丢失走上述恢复规则。取消等候超过10秒显示“仍在等待模型停止”，提供诊断，不假装资源已释放。停止加载允许留下已完成的空闲驻留模型，取消一个排队者不终止其他请求。

关闭最后窗口不退出；菜单/应用重新激活可恢复窗口。退出时有己方聊天或己方worker上的其他活跃推理，提示“停止任务并退出 / 继续运行”。外部服务仅取消本App请求，不停止外部任务；无活跃任务不提示。先保存checkpoint，再取消等待，再保存终态，最后drain己方worker。正常等待30秒仍未结束时显示“继续等待 / 强制退出”；强制只终止己方Process（TERM后5秒仍存活才KILL），记录interrupted，不报告正常回收。存储失败阻止静默退出并允许重试保存；用户明确强制退出可丢失尚未保存数据，提示具体风险。父进程崩溃由EOF触发worker drain，30秒上限后异常退出。

## 5. GUI 与聊天持久化（M2-R04、R05）

模型为默认入口；一级导航仅模型、测试，服务状态位于全局底部。当前模型页读取服务模型库，历史会话路径只保留历史关联，不重建可选模型；目录选择复用模型导入流程，详情带入模型新建测试。测试区内部会话列表、聊天详情；原生目录选择、新会话、发送、停止、重试、服务来源/连接状态、独立模型状态、诊断入口。M2不展示不可用的下载/工具按钮。参数默认折叠，仅提供当前真实支持的输出上限和温度；不提供未经验证的上下文/思考控件。重试保留旧结果与分支上下文选择；停止、失联和保存状态分别表达。仅Qwen2.5 0.5B当前实测，其他可估算架构标“未在本机验证”，不伪称完整兼容。路径失效可重新选择，不改变旧消息的模型快照。

每会话最多一个生成，全App最多一个活动聊天生成（外部client仍由Core排队）；生成中可浏览其他历史，返回后继续显示原请求。基础Markdown支持段落、行内强调/代码与链接，生成时分段节流渲染，禁止每token全文Markdown解析；代码/链接不执行。用户向上滚动不强制拉回底部，提供回到底部操作。

ConversationStore 正式初始 schema（磁盘版本 2.0.0）：VersionedSchema；Conversation(id/title/createdAt/updatedAt/selectedLeafID/localModelPath)，Message(id/conversationID/parentID/sequence/role/contentBlocks/createdAt)，GenerationAttempt(id/requestID/instanceID/userMessageID/assistantMessageID/retryOfID/modelSnapshot/sampling/status/lastSequence/usage/errorCode/createdAt/updatedAt)。开发期 V1 数据已在首版源码发布前完成一次性备份和转换；生产代码只用存储自己的内容/参数编码，不依赖 HTTP DTO。内容块用显式带type Codable值，当前仅text，不持久化Swift enum内存表示；不存MLX对象或ModelContext。路径为本地用户数据，不输出诊断。预留内容块边界，不建空附件系统。

重试不消费输入框草稿；只有新发送成功创建 pending 后才清空当时冻结且未被用户修改的草稿。重试是同一个userMessage下的新assistant attempt，保存retryOfID与原结果；上下文冻结为该user的祖先成功轮次，新请求新UUID。UI可切换查看旧attempt，不覆盖、不把多个重试结果同时作为上下文。后续发送基于所选成功分支；failed/cancelled/interrupted轮次（包括对应user）不入上下文，和M1一致。stop/length可入上下文，length可见；超上下文明确报错，不截断。活动分支期间禁止切换其模型/重新选择上下文。

先原子save用户消息+pending attempt再发送HTTP；保存失败不发请求。由单一ModelActor在非主线程上下文写入，UI只消费Sendable snapshots。同进程的SwiftData schema/ModelContainer构造经专用actor串行化，避免真实并行建库时触发底层共享元数据竞态；保存仍由各store actor隔离，不放到主线程。每250ms或累计8KiB checkpoint（先到者），每次保持消息文本+lastSequence+状态一致；最终明确save，不能依赖autosave。MainActor刷新最多20Hz，完整文本按有界增量累计，不丢弃持久内容。回复头部、文本段与操作尾部使用单层稳定ID的惰性列表，避免嵌套惰性高度估计导致“回到底部”不到位；终态也显示在输入区旁。

会话摘要每页100项，不读取消息正文；详情仅按选中会话加载，每页最多8条回答且正文合计预算4MiB，单条超预算时独占一页并完整显示（已有单回复上限16MiB）。翻页替换当前页及其滚动视口，不无限追加或保留已移出页的布局；翻页从页首阅读，新发送跟随末尾。每条回复按自身状态选择流式/已结束呈现，不因其他请求开始而重新切换。磁盘历史不截断、不删除。对话排序、会话内回答排序及待恢复状态使用索引。选择切换用读取标识丢弃迟到结果；未保存 live 回复独立保留，流式期间只更新活动回复，既有分段缓存按ID/序号复用。生成上下文仍来自完整成功分支，达到已有输入上限即明确拒绝，不因当前显示页数改变上下文。

启动重开仅分页读取pending/streaming/stopping元数据并变interrupted、save，不重新请求。保存失败：取消在途生成，UI保留内存文本显示“未保存”并可重试；不继续无界积累。打开库失败显示真实可诊断错误，不删库、不回退空库；终态写失败不显示已保存。启动对话目录独占锁防双writer；不直接操作SQLite。用户删除对话只删除明确选中历史，不删除模型；活跃会话须先停止，含未保存回复的会话须先成功保存，删除入口与控制器复用同一允许条件。

## 6. 诊断与打包（M2-R06）

OSLog subsystem `dev.mox`，按process/server/client/gui/storage/runtime关联instance/request；沿用BackendFailure脱敏。GUI显示服务来源、版本、错误码、阶段和requestID，提供显式导出脱敏JSON诊断。ring同时限制256条/256KiB，单条4KiB；不含正文、完整路径、凭据或上游任意描述。存储边界明确记录open/recover/fetch/save阶段；仅允许NSCocoaErrorDomain/NSPOSIXErrorDomain的domain/code，其余脱敏，禁止任意description/userInfo。UI及导出包含最近一次存储操作失败，未产生live请求的启动失败也可定位。worker stdout/stderr以非阻塞POSIX read、最多4KiB的读取块异步持续排空，不积累无换行文本；仅保留字节计数与进程退出状态，原始正文不导出。故障阶段与安全错误码保留在结构化 OSLog；不因满管道阻塞退出。

Xcode项目提供App与XCUITest targets，库由SwiftPM管理；构建脚本产出独立arm64 Mox.app，Contents内含同buildID worker、Metal库、资源bundles和许可证。bundle-relative定位且检查缺失，App不依赖PATH/源码目录/brew/Python。工具脚本可用开发工具，用户运行不可依赖它们。worker缺失或App内Metal资源缺失必须在启动时明确失败，不能依赖工程路径回退。默认本地ad-hoc签名，正式分发后置。

CLI与GUI均提供Debug/Release：`scripts/build-m2.sh Debug`、`scripts/build-m2.sh Release`。App分别在`.build/m2/{Debug,Release}/Mox.app`，独立CLI及其资源在`.build/m2-worker/{Debug,Release}/`。Debug使用无优化、DEBUG条件及调试信息，Release使用优化和dSYM；嵌入worker必须与App配置一致。两种配置均保留安全错误/生命周期日志与显式诊断导出，Debug增加无正文/凭据的传输状态日志；Release也允许通过`MOX_PERFORMANCE_REPORT`输出有界数值性能报告。buildID标识共享生产源码，配置名另见CLI `--version`、启动日志和GUI诊断。CLI自启由dyld定位当前可执行文件，不依赖argv[0]或工作目录。

## 8. 人工验收场景

工作台入口检查：冷启动默认模型页；添加本地目录后进入详情，点击“测试此模型”新建会话。模型页显示最近使用的引用而非安装清单，文件与运行状态分开。测试区可收起会话列表，查看名称、模型、时间与状态；参数默认折叠。关闭窗口后重开保留当前模块。

重试结果检查：同一会话至少两轮，停止后重试最后一轮；通过上一/下一结果查看旧部分回复。浏览旧结果不改变上下文，只有显式“从此回复继续”改变分支。失联与未保存分别提示，不将停止意图等同资源已释放。

实现后报告提供准确App路径、外部serve命令、准备模型与诊断位置；用户只需验证下列体验，不承担基础正确性测试。

1. 无服务首次打开：选本地目录，看到来源“由此App启动”、独立的模型加载状态、中文流式回复；错误模型目录提示可理解且可重选。
2. 长回复与停止：滚动历史不跳回；加载/长输入准备或输出时停止，看到正在停止，结束后再问成功；重试保留原部分回复。
3. 历史：关闭窗口后重新打开，聊天仍在；退出重开，成功/取消结果保留；异常结束后显示中断，不自行继续生成。
4. 外部服务：先前台启动，App显示外部来源；退出App后CLI仍可聊天。版本不符/端口假服务给出可定位错误，不暗启第二实例。
5. 故障恢复：生成中服务退出，部分文本保留并提示失联；重新连接后显式重试，新回复不被旧事件覆盖。
6. 退出与保存：活跃任务退出弹出停止并退出/继续；选择继续保持任务；正常退出后己方worker关闭；保存失败有未保存提示，不能伪装保存成功。
