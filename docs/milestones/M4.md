## 协议契约

下列为 **Mox 0.1 支持子集**，不是声称两家 API 的完整实现。解析器对已知但不支持的语义字段和未知非空字段返回 400，指出安全的字段路径；不得用宽松 Decodable 静默丢弃。允许标准 SDK 会附带但不改变语义的空/默认字段，逐项列入 fixtures；不得以“忽略所有 extra”实现。请求 JSON 深度、字符串、工具数量与 schema 大小设命名上限，16 MiB body 上限在聚合前执行；输入仍受 Core 1 MiB 原文、8192 token、模型 context 与资源预算限制。精确值由所属模块单处定义，测试记录。

### OpenAI Chat Completions

- 请求：`model` 为本服务已安装 alias 或精确安装标识；`messages` 依原顺序接收 `system`、`user`、`assistant` 的文本字符串或纯文本块，以及 `assistant.tool_calls` 和 `tool` 的 `tool_call_id` 文本结果。`developer`、`function` 旧角色、`name`、图片/音频/视频、refusal、未识别块拒绝。工具调用必须由紧邻的上一 assistant 轮次定义，ID 唯一，多个结果可用连续 `tool` 消息逐一匹配；未收齐前不得插入无关 user/assistant/system 消息，不能丢弃缺失/多余结果。服务不自动补历史。
- 接收 `stream`（默认 false）、`temperature`、`top_p`、`max_tokens`、`stop`（字符串或有限字符串数组）、`tools`（仅 `type:function` 的 name/description/JSON object parameters）、`tool_choice` 的 `none`/`auto`，`stream_options.include_usage`。`n` 仅 1，`parallel_tool_calls` 仅 false，`response_format` 仅缺省或 `text`；其他值拒绝。`required`、指定函数、strict schema、`seed`、`logprobs`、penalties、`max_completion_tokens`、prediction、modalities、audio、service_tier、store、metadata 等本阶段拒绝。缺省 `tool_choice`：无工具为 none，有工具为 auto。`none` 不得生成结构化工具调用；auto 仅在模型能力经验证时接受，否则 400 `unsupported_input`。这里的工具选择限制是明确的 0.1 产品边界，后续若要支持强制选择须先证明运行时可执行该语义，不能只靠提示词伪装。
- 非流式成功：`chat.completion`、稳定本次 ID、实际模型、单 choice 的 assistant（文本或 `tool_calls`），`finish_reason` 为 `stop`/`length`/`tool_calls`，`usage.prompt_tokens`/`completion_tokens`/`total_tokens` 来自已执行推理的真实计数。没有可证计数时失败，不填估算或零。无工具调用时 `tool_calls` 不出现或为 null，遵循 SDK 解码实测。
- 流式：`text/event-stream` 的 `data:` ChatCompletionChunk；首块 `delta.role=assistant`；文本 delta 保持 UTF-8 顺序；工具按 `index`、稳定 `id`、function `name` 起始，再发可拼接的 `function.arguments` JSON 字符串分片，末块 finish_reason；末尾 `data: [DONE]`。`include_usage=true` 时在 DONE 前发 `choices:[]` 的最终 usage chunk，先前 chunk usage 为 null/省略；false 时不承诺末尾 usage chunk。ID/model/created 在同一响应一致。工具参数只有通过完整 JSON 与 schema 基本校验后才可标 tool_calls 终态；不把尚未确认的模型文字伪装为已完成调用。部分流失败按下文错误处理。

### Anthropic Messages

- 必须要求 `anthropic-version: 2023-06-01`；`x-api-key` 单独校验，`anthropic-beta` 非空一律拒绝，避免虚假 beta 语义。`model` 同上；`max_tokens` 必填且为正。`system` 接收字符串或纯文本块；`messages` 按原顺序接收 user/assistant 的文本块，assistant `tool_use`（id/name/input JSON object），user `tool_result`（tool_use_id/纯文本/is_error）。不接收图片、文档、thinking、server tools、cache_control、citations 或其它内容块。多个 tool_result 必须在紧随调用的同一 user 消息中收齐，可与文本块混排；不得跨越无关轮次，保留块顺序与错误标志。
- 接收 `stream`、`temperature`、`top_p`、`stop_sequences`、`tools`（仅客户端自定义 name/description/input_schema JSON object）、`tool_choice` 的 `auto`/`none`。`any`、指定 tool、`disable_parallel_tool_use` 为 true、fine-grained streaming、JSON/结构化输出、`top_k`、`metadata`、`service_tier` 等拒绝；缺省有工具时 auto、否则 none。文本与工具可混合且多个 tool_use 块按生成顺序输出。无工具能力模型带工具请求明确拒绝。
- 非流式：`type:message`、assistant role、有序 `content` 文本/tool_use 块、`stop_reason` 为 `end_turn`/`max_tokens`/`stop_sequence`/`tool_use`；`usage.input_tokens`/`output_tokens` 为真实计数。没有缓存 token 时不伪造 cache 统计。`stop_sequence` 返回实际命中的序列，否则 null。
- 流式：严格按 `message_start` → 每块 `content_block_start`、零或多个 `content_block_delta`、`content_block_stop` → `message_delta`（最终 stop_reason 与累计 usage）→ `message_stop`。文本用 `text_delta`；工具输入用 `input_json_delta.partial_json`，块开始携带 id/name 和空 input；各 index 稳定且拼接后是合法 JSON object。`message_start.usage` 包含真实 input token，最终 message_delta 含真实累计 output token。可发 ping；不能把 OpenAI `[DONE]` 发到 Anthropic 流。

### 共同生成语义与错误

- 参数在准入前解析并冻结；`stop`/`stop_sequences` 必须真正在生成边界生效，跨 token/Unicode 分片正确，命中序列不出现在用户文本；它与自然 EOS、长度耗尽、工具调用分别映射停止原因。模型特殊 token 或未知上游停止原因不得凭猜测映射为成功。取消不返回伪造的 `stop`/`end_turn`，客户端主动断连则取消并等待后端及 lease 释放；若连接仍在，使用协议错误终止流。
- 错误在 headers 前给协议 JSON：OpenAI `error:{message,type,param,code}`，Anthropic `type:error,error:{type,message},request_id`。分类：400 格式/不支持，401 凭据，404 模型，409 状态冲突，413 大小，429 队列，503 不可用，500 意外错误；资源不足用稳定 `resource_exhausted` code 并取 503。认证检查早于模型信息泄露。SSE headers 后失败发相应协议的 `error` 事件/错误 data 并关闭，绝不再写第二个 HTTP 响应、成功终态或 DONE；SDK 可能将其解释为异常或流中断，测试必须核对。request ID 可用于脱敏诊断关联。
- 每请求有服务拥有的 task、单个 Core GenerationHandle 和唯一终态；真实 HTTP 写入 await 背压，写入超时/断连取消并等待；客户端长时间不读须有有界队列与期限，不能让 GPU 或内存无限积压。正常结束 flush/end；服务关闭 drain 所有在途任务。公共请求默认不记录正文、参数、工具输入/结果、API key、Authorization、敏感 URL。日志只留协议、阶段、时长、稳定错误码、request/model 安全标识和计数。失败路径能在 GUI 诊断中定位。
- 对未读完 body 就能拒绝的请求，先写有界协议错误并关闭连接，不等待客户端继续上传；GET 带 body 明确拒绝。已鉴权的请求体读取有绝对期限，空闲 HTTP/1 连接也有限期；超过 16 MiB 的声明长度和聚合中超限都释放连接配额。用未终止 chunked 真 socket 测试 401/403/413、连接关闭及后续正常请求。

## 工具调用与模型验证

- 领域保留 JSON 值类型的 schema/arguments 和有序内容块；工具调用 ID 由 Mox 为每次调用分配并在同一响应、下一轮历史和协议转换中保持一致；ID 不由模型自由文本信任。参数增量只在上游解析器确认为工具区域后发出，不能泄露半个调用为普通正文。参数完整性、schema object/name、数量与字节上限校验失败，给明确失败，不静默改成文本成功。多个调用按顺序/索引保留。工具结果仅进入下一次显式请求；Mox 不调用任何函数、网络或文件来执行它。
- 优先真实验证模型：`mlx-community/Qwen3-0.6B-4bit`，优先固定 HF commit `73e3e38d981303bc594367cd910ea6eb48349da8`，安装时记录文件 digest；其 Qwen3 架构和聊天模板/工具解析器须先在**锁定** MLX LM 3.31.4 上完成能力探针。模型卡和 Qwen 官方资料仅证明候选方向，不替代真机可用性。若该模型在当前 SDK、内存预算或实际调用稳定性下不合格，选同系列可运行的 1.7B 4-bit，记录更换原因与精确 revision；不能用合成调用替代真实验证，也不能在失败时称工具能力已交付。
- 测试定义一个纯函数 `lookup_code(code)`：仅映射固定内存字典（如 `MOX-7 → blue`），未知返回固定错误文本，无文件/网络/进程副作用。两协议各完成请求→模型产生结构化调用→测试程序按 schema 检查 name/参数/ID→测试程序计算结果→带同一 ID 与完整历史再次请求→模型给出最终文本。验证 auto 与 none、单/多调用 fixtures、参数跨分片、错误 tool_result、无工具模型拒绝；不要求模型自由文本逐字相同，断言结构、顺序和因果。强制工具选择不在 M4 支持范围，测试断言 400。
- 现有 M1 callback 路径提供有界输出但只产生文本；上游另有 `ToolCallProcessor` 与 Chat.Message 工具元数据，不能直接切换到其可能无界的 AsyncStream。实施时在相同有界/取消/usage 边界内接入经锁定版本核对的 parser；验证 schema 传递、EOS flush、真 token 计数与停止原因。若 parser 不能满足可靠增量，先有界缓冲工具区域、仅在完整解析后按合法事件分片输出，且不将解析失败报为成功；不要自造模型格式的第二套权威解析器。
- 实施核验：锁定版 `ToolCallProcessor` 对一个 chunk 中先出现其他 `<...>` 标签再出现 `<tool_call>` 不会重新扫描；MLX adapter 将解码内容按 Unicode 标量逐个交给官方 parser，并在完整工具调用出现时先 flush 此前普通文本，再发工具事件。工具参数待完整解析后通过协议层分片；这不是模型边生成边透传参数。Qwen3 使用上游聊天模板的 `enable_thinking=false`，防止 `<think>` 区域作为正文泄露。工具能力仅对来源、固定 revision、权重和 tokenizer 摘要均匹配上述真机验证产物的受管安装开放；仅凭 `model_type=qwen3` 或未附受管清单的导入引用不能声明工具能力。今后扩大能力表须先加实际模型验证。

## 模块与服务边界

跨模块契约由[技术设计 §7–§10](../architecture/TECHNICAL-DESIGN.md)维护；这里规定本阶段交付行为。

| 边界 | M4 必要变更 |
| --- | --- |
| Domain/Core | 将已有只读文本校验扩展为有序文本/工具块、工具选择与 stop 结果；统一输入准入、资源、lease、取消等待、真实 usage 与错误。Core 对 HTTP DTO 无依赖。GUI 文本聊天继续走同一生成用例。 |
| MLX adapter | 在现有官方 generate callback、有界队列与同步回收之上接入锁定 SDK 的工具模板/解析器和 stop 匹配；支持能力探测，不能把所有已安装模型标为工具可用。 |
| 协议适配 | OpenAI/Anthropic 各自 DTO、严格字段校验、事件编码和错误映射，只在传输边界；不得写入 SwiftData record 或反向污染领域类型。保留两种 wire 差异，不复制 Core 规则。 |
| Server/Client | 私有管理 listener 仍只对 GUI/CLI，使用实例级管理凭据；公共推理 listener 单独 loopback、默认关闭，使用独立持久 API key（Keychain），启动/停止与绑定失败可诊断。公共 key 不能调用 `/mox/v1/*`，管理 token 不可作为公共 key；不在公共 discovery 暴露管理 token。Origin 非空的浏览器跨站请求拒绝，OPTIONS 不提供宽松 CORS。公共 listener 只绑定 `127.0.0.1`，不接受配置成 LAN。公开 `/v1/models` 只列已安装可供请求的模型及 alias，不泄露本地路径、来源凭据或管理状态。 |
| GUI/CLI | App API 页面显示关闭/运行/错误、实际 URL、可复制的两协议最小连接示例、key 生成/重置/显示操作及脱敏默认展示；重置使旧 key 失效，关闭拒绝新公共请求并 drain/cancel 活跃请求，不停私有服务和下载。外部 owner 服务由同一私有管理接口管理公开开关；GUI 不能越权停其进程。CLI serve/status/doctor 给出相同状态与诊断；不要求用户预装 CLI 才能用 App。 |

API key 仅 Keychain 持有，以数据根身份确定 Keychain 项，不写入持久配置、discovery/log/URL。持久设置只保存启用状态；每次启动由系统动态分配 loopback 端口，App 显示实际绑定端口，客户端需读取当前连接信息。首次启用若无 key 原子生成，Keychain 失败保持关闭并提示；重启按设置恢复，绑定失败须报告，绝不悄悄退到无鉴权。关闭 App 时仅停止自己创建的 worker；外部服务上的 API 开关仍由其 owner 进程持续提供。

管理状态携带不含密钥材料的凭据版本 ID。GUI 显示密钥后如 CLI 或其他管理客户端重置密钥，下一次状态刷新须清除过期明文，避免继续展示或复制失效凭据。并发开关操作按到达次序串行完成，返回状态应反映操作完成后的真实 listener；恢复启用时 Keychain 错误保留稳定诊断码。

## 用户人工验收（交付时报告给出准确 App 路径和一键测试命令）

1. 在 Release App 下载一个公开模型、查看详情并聊天；确认无需终端或额外运行时，失败提示可理解。
2. 停止长回复再生成，退出/重启后查看模型与测试会话；观察中断与恢复状态。
3. 在 App 开启 API，查看并复制地址/key 与两协议连接示例；确认信息清晰、密钥默认遮蔽且操作顺手。两 SDK 的协议和工具往返正确性由自动验收承担。
4. 重置 key、关闭并重新开启 API，查看状态与诊断文案是否明确。旧 key 拒绝、关服拒绝连接、压力与资源回收由实现者自动验证。

## 首版治理补充（2026-09-30）

Core 累计输出上限为 16 MiB、工具调用最多 32、单次工具参数最多 64 KiB，与等待缓冲限制独立；超限须等待实际停止再返回 resourceLimit。工具 schema 校验非空名称、JSON object、顶层 type=object 与大小/数量，完整 schema 传给模型，客户端工具执行方验证业务参数；不承诺通用 JSON Schema 求值。私有管理探活 15 秒，来源解析/计划/创建与显式加载等待 15 分钟，取消使用独立短期限，不自动重放副作用请求。最新实际证据见[治理报告](../acceptance/source-release-governance-2026-09-30.md)。
