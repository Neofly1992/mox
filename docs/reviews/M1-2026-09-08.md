## R1 [P2] 泛化底层错误前未保留可定位的诊断

位置：Sources/MoxCore/RuntimeCoordinator.swift:180–184；Sources/MoxMLX/MLXBackend.swift:48–56。

processor/tokenizer/生成抛出非 MoxError 时，Coordinator 丢掉底层原因，仅返回 generationFailed，并提示 inspect runtime diagnostics，但自身日志没有该原因。加载路径仅记录 Swift 错误类型；例如多个 DecodingError 都无法区分缺失字段与具体配置位置。用户随后调试 GUI 时，request ID 只能找到“失败”，不足以定位哪个阶段、哪类资产或错误码。

应在边界建立脱敏的结构化错误分类/诊断上下文，保留 stage、底层类型及可安全记录的 domain/code/coding path 等信息；对调用者继续返回稳定安全文案。不能直接公开插值任意 error.localizedDescription，避免 prompt、路径、token 被上游错误带入日志。为不同注入错误验证可区分性与敏感字段不泄漏。该项对应 M1-R10 和全局可诊断原则，建议 M2 前关闭。
