# M3 同会话 review-agent 自审与修复

状态：2026-09-24 实现者按 review-agent 流程完成只读审查，随后根据用户指令修复。此记录不是独立会话审查，也不代替用户人工验收。审查对象为 `codex/rewrite` 工作区未提交的 M3 代码与相关产品契约；审查时把未跟踪的新文件纳入，未仅依赖 `git diff`。

| 优先级 | 已确认问题 | 修复与针对性证据 |
| --- | --- | --- |
| P1 | 过期来源配置请求先覆盖 Keychain 凭据，再遇 revision 冲突 | 新凭据使用独立 Keychain 引用；更新成功才启用，失败清理暂存引用，成功后清理已不用的旧引用。`stagedCredentialDoesNotOverwriteCommittedCredential`、`staleSourceUpdateCannotReplaceCommittedCredential` 通过。 |
| P1 | 受管文件已丢失时，删除先持久化 pending，随后因文件不存在失败，并阻塞以后启动 | 缺失受管目录视作文件侧删除已完成，仍持久化移除记录；`missingManagedFilesCanBeRemovedAndRecovered` 通过，GUI 在 missing 状态允许移除。 |
| P1 | 新版本安装没有切换当前引用 | 同 registry/repository/variant 使用稳定当前 alias，旧快照保留精确版本 alias；成功安装和 alias 切换在同一库快照保存，可显式选回旧版，CLI 聊天按 alias 在请求开始时冻结路径。`newRevisionSwitchesPreferredAliasAndOldVersionRemainsSelectable`、`installedAliasResolvesToFrozenModelPath` 通过。 |
| P2 | 获取表单把已配置镜像的空初值当成移除镜像 | 表单按有效来源预填 endpoint/mirror；切换来源或输入新 origin 时同步处理镜像。真实 GUI 回归结果见交付报告。 |
| P2 | default-source 保存成功，但 CLI 获取仍固定官方 origin | CLI 省略 provider/endpoint 时使用配置的默认 registry，显式 provider 时优先该协议的默认来源；`defaultSourceSelectionUsesConfiguredRegistry` 通过，真实来源 CLI 验证见交付报告。 |
| P2 | 导入失败前就将目录设为聊天模型 | 导入成功后才切换；返回规范路径，重复选择已导入目录复用现有引用；核心回归通过。 |

审查中另发现受管模型详情文字误称为用户自管文件，已按所有权显示；缺失文件时仍允许移除。未验证的真实私有镜像、实际断网、运行中删除竞态及 macOS 15 真机继续如实列于 M3 报告。完整测试、最终构建 ID 与人工状态以 [M3 交付报告](../acceptance/M3.md)为准。
